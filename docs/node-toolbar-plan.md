### 1.3 UI 设计要点

1. **一级只放高频项，其余收进「更多」**，避免工具栏无限变长。
2. **按钮状态动态计算**，例如无音轨时「分离音视频」禁用并给 tooltip「当前视频无音轨」。
3. **自定义工具栏**支持固定 / 取消固定，并持久化。
4. 多数工具不是「一键执行」，而是「进入某种交互模式」（选片、拖相机、涂蒙版、框选）。按钮只是入口，真正的成本在交互面板。
5. 付费项有钻石标记；CineLab 无付费体系，不需要复刻，可改为「需模型」标记。

### 2.1 已有

- 节点选中态工具栏：尺寸 + 下载 + 展开（`CineNodeView.tsx`）。
- 版本栈：`outputs[]` + `selectedOutputId`，新结果自动置顶。

- 模型配置开放：`models.json` + HTTP 模板，可接专用 API。

### 2.2 缺口

1. **没有媒体处理能力**：未引入 ffmpeg / ffprobe，本机 PATH 也没有。
2. **资产元数据不全**：只有 width/height，缺 duration、fps、hasAudio、codec。
3. **没有「操作」抽象**：只有按节点类型选生成模型，没有「对当前素材执行某操作」的注册表。
4. **没有交互组件**：裁剪框、时间轴、宫格选片、字幕框选均无。
5. **refs 只支持图片**：视频 / 音频参考注入未实现，视频编辑类功能被卡住。
6. **工具栏在画布缩放时会跟着缩小**，按钮数量变多后可读性会下降，需要重新考虑定位与尺寸策略。

## 4. 架构建议

### 4.1 操作注册表

不要为每个工具新增一个 `Capability`。新增一层「操作」：

```ts
interface NodeOperation {
  id: string
  label: string
  kinds: NodeKind[]
  icon: IconName
  executor: 'local' | 'model'
  preferredCapability?: Capability
  buildPrompt?: (params: Record<string, unknown>) => string
  outputMode: 'version' | 'nodes' | 'both'
  enabled?: (ctx: OperationContext) => boolean
}
```

- `local` 操作直接走 IPC；
- `model` 操作复用现有生成队列；
- `enabled` 负责无音轨、无输出、未配置模型等禁用态；
- UI 只渲染注册表，新功能只需注册，不改工具栏组件。

### 4.2 执行器分层

1. **本地执行器**：主进程子进程跑 ffmpeg / nativeImage，输出 buffer 后走 `ingestAsset`。
2. **模型执行器**：复用 `generationQueue`，把操作参数编译成 prompt + refs + params。
3. **专用执行器**：确实需要专用 API 的（超分、抠图、视频编辑），在 `models.json` 里用独立 adapter / HTTP 模板，不混进通用 i2i。

### 4.3 结果回写三策略

| 类型 | 策略 | 示例 |
|---|---|---|
| 增强类 | 同一节点新版本 | 裁剪、画面裁切、打光、人像 |
| 拆分类 | 新建多个节点并自动布局 | 宫格切分、抽帧、分离音视频 |
| 派生类 | 新节点，保留原图 | 多角度、全景、九宫格生成 |

所有新建的派生节点必须自动与源节点建立 `source → target` 连线，包括宫格切分、抽帧、分离音视频、后续九宫格/多角度等。版本回写（裁剪、截取、画面裁切）不新建节点，不额外连线。

### 4.4 数据模型扩展

`OutputRef` 增加可选字段（向后兼容）：

```ts
duration?: number
fps?: number
hasAudio?: boolean
op?: string        // 'grid-split' | 'trim' | 'extract-audio' ...
parentOutputId?: string
```

`CineNodeData` 不需要大改；`addNode` 需要扩展为可带初始 outputs / 标题 / 位置偏移。

### 4.5 工具栏 UI

- 一级 4–6 项，其余进「更多」；
- 右侧保留「下载 / 展开」，可加「参数」；
- 宽度超出节点时改为居中 + 最大宽度钳制；
- 画布缩放时工具栏保持可读尺寸（必要时改 `createPortal` + 屏幕坐标，参考 PromptBar）；
- 「更多」中暂不可用的项以灰度显示，点击提示「未配置模型 / 暂未开放」，不要隐藏，形成能力地图。

## 6. 技术要点

### 6.1 ffmpeg 打包

- 依赖：已接入 `ffmpeg-static` 5.3.0 + `ffprobe-static` 3.1.0。
- 体积实测：`ffmpeg.exe` 约 83MB，`ffprobe.exe` 约 63MB。
- electron-builder 需把二进制从 asar 解出（`asarUnpack` 或 `extraResources`）。
- 运行时解析路径：开发态取 node_modules，打包态取 resources。
- 启动时自检：`ffmpeg -version`，失败则禁用所有本地视频操作并给明确提示。
- 体积：预计安装包增加 70–90MB，已确认接受。

### 6.2 任务执行

- 所有媒体任务走主进程，渲染进程只传参。
- 长任务放 `utilityProcess` 或独立子进程，避免阻塞主进程 IPC。
- 进度解析：优先 ffmpeg `-progress pipe:1`，解析 `out_time_ms` / `frame`。
- 取消：记录进程句柄，Windows 下用 `taskkill /PID /T /F` 杀进程树。
- 临时文件统一放项目 `.cinelab/tmp/`，任务结束或启动时清理过期文件。

### 6.3 元数据

- 视频生成 / 导入后立即 ffprobe：duration、fps、width、height、codec、hasAudio。
- 旧资产缺字段时按「未知」处理，相关按钮显示禁用或提示「无法读取元数据」。
- `hasAudio` 同时用于「分离音视频」和「工具栏禁用态」。

### 6.4 宫格切分

- 输入：当前选中输出；行列数（2×2 / 3×3 / 4×4 / 5×5 / 自定义）。
- 边界：按图片真实宽高计算，最后一行 / 列取余数，避免越界。
- 选片：进入沉浸模式，点选需要的格子；支持全选。
- 输出：每个选中格子一个图片节点，自动排列在源节点右侧；标题带序号。
- 保留原图，不回写源节点版本栈。

### 6.5 抽帧

- 模式：首帧 / 尾帧 / 当前帧。
- 首帧 time=0；尾帧 time=duration-0.05；当前帧从节点 `<video>` 的 `currentTime` 读取。
- 单帧 PNG 保留原始分辨率，落盘后新建图片节点，并自动连线源视频节点。
- 不生成多页宫格，不做抽帧密度 / 分页。

### 6.6 分离音视频

- `ffprobe` 判断音轨；无音轨直接禁用。
- 有音轨：输出无声视频 + 音频两条资产。
- 容器兼容：优先 `-c copy`；不兼容时音频转 AAC / MP3，视频转 MP4。
- 输出两个节点：视频节点 + 音频节点，自动连线可选。

### 6.7 裁剪 / 画面裁切

- 图片比例裁剪：居中裁切，越界钳制。
- 图片自由裁剪：前端选框 + `media.cropImageRect`，按原图坐标换算。
- 视频画面裁切：ffmpeg `crop=w:h:x:y`，宽高向下取偶（H.264）。

### 6.8 框选去字幕

- 前端在视频上框选字幕区域，坐标按原视频尺寸换算。
- ffmpeg `delogo` 区域擦除，坐标 clamp 到画面内。
- 复杂背景效果有限，UI 已提示。
- 智能去字幕仍需要视频修复模型，暂未接入。

### 6.9 兼容与回归

- 旧 `OutputRef` 无新字段：全部可选，读取时兜底。
- 旧项目画布不需要迁移。
- 打包后必须验证 ffmpeg 路径、中文路径、空格路径。
- 视频任务失败不能污染版本栈。

## 7. 风险

1. **长视频处理耗时与磁盘占用**：抽帧、裁切会产生大量中间文件，需要配额与清理策略。
2. **Windows 进程取消**：只 kill 父进程可能留下 ffmpeg 子进程，必须杀进程树。
3. **打包路径**：asar 内二进制无法执行，必须解包；CI 与本地路径不同。
4. **工具栏缩放可读性**：现有工具栏随 React Flow 缩放，项目变多后按钮会过小。
5. **模型能力差异**：P1 的提示词工程效果取决于用户接的 i2i 模型，需要在 UI 上标注「效果由模型决定」。
6. **语义不确定**：图层分离、720 全景的具体产品定义仍需实测 LibTV 后再定。
