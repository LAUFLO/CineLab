# CineLab UI 打磨方案

日期：2026-11-21
状态：已实施（P0–P3 完成；MCP 设置入口待后续）
适用版本：v0.5.0

## 1. 背景

近期连续加入了模型适配、MCP、导演台、拉片、多结果等能力，画布与设置页的交互细节开始暴露问题：

- 参数值有原始数字，缺少单位；
- 节点被选中时，连线没有联动高亮；
- 添加节点菜单靠近窗口底部会被裁切；
- 上传素材节点仍显示提示词栏，节点尺寸也没有完全按素材比例适配；
- 节点两侧的加号可见性不足；
- 快捷键仍是硬编码，设置页只有占位；
- 技能页仍是列表 + 编辑区，默认技能也混在其中；
- “基本设置”承担了过多无关内容。

本方案覆盖 9 项 UI 打磨，按 P0–P3 分批实施。

## 2. 目标与原则

目标：

- 先解决遮挡、看不清、单位缺失等直接影响使用的问题；
- 不改变模型请求体和项目文件格式的既有语义；
- 素材节点保持“素材”语义，同时保留生成入口；
- 设置页按能力重新分组，不丢失既有入口；
- 快捷键自定义覆盖应用、画布、剪辑室和导演台。

原则：

1. 复用现有组件、store 和 IPC，优先扩展现有能力。
2. 新增持久化字段必须同时写入 `src/shared/canvas-schema.ts` 与 `src/shared/project-schema.ts`，避免 zod strip。
3. 瞬时 UI 状态不写回项目文件。
4. 涉及全局键盘监听、共享 `Menu`、节点尺寸的改动，必须单独回归。
5. 每批完成后运行 `typecheck`、`test`、`check:ui`、`check:docs`，并用隔离实例做界面验证。

## 3. 逐项方案

### 3.1 参数单位

**现状**

- `src/renderer/src/canvas/promptbar-model.tsx` 的 `paramLabel()` 对数字直接 `String(value)`，汇总显示 `5`。
- `src/renderer/src/canvas/promptbar/ParamPanel.tsx` 只对 `key === 'duration'` 显示 `${value}s`，`seconds` 不识别。
- 分辨率选项一般已带 `720P / 2K`；比例 `16:9` 本身自解释。

**方案**

- 新增统一的 `paramValueLabel(def, value)`：
  - `duration` / `seconds` 数字追加 `s`；
  - `resolution` / `size` 的纯数字追加 `P`，已有单位保持原样；
  - `ratio` / `aspect_ratio` 保持 `16:9`；
  - boolean / select 沿用现有逻辑。
- `PromptBar` 的 `paramSummary` 与 `ParamPanel` 都改用该函数。
- 补充 `seconds`、`aspect_ratio` 的自定义输入和默认允许自定义键。

**验收**

- Agnes 视频显示 `5s · 16:9`；
- 时长滑块与汇总一致；
- 自定义分辨率 `1080` 显示 `1080P`；
- 现有参数请求体不变。

### 3.2 选中节点连线光效

**现状**

- `src/renderer/src/canvas/edges/FlowEdge.tsx` 只读取 `selected`（连线自身选中）。
- `docs/ui-spec.md` 已定义“所在节点被选中：`--link`、2px、4px 外发光”，代码未实现。

**方案**

- `FlowEdge` 补 `source` / `target`，通过 React Flow `useStore` 的 primitive selector 读取两端节点 `selected`。
- `highlighted = selected || sourceSelected || targetSelected`，复用 `--link` 与 `--glow`。
- 连线总数超过 300 时关闭 `drop-shadow`。
- 不把高亮写入 `canvas.edges`，避免持久化污染。

**验收**

- 选中节点后左右两侧连线发光，取消选中恢复；
- 拖动节点无明显额外卡顿；
- 连线自身选中仍保持现有视觉。

### 3.3 添加节点菜单裁切

**现状**

- `src/renderer/src/components/ui/Menu.tsx` 只把左上角 clamp 到视口内，没有按菜单高度计算。
- `AddNodeMenu` 的 `max-h-[calc(100vh-120px)]` 不是按锚点剩余空间计算，靠近底部仍会超出。

**方案**

- `Menu` 增加 opt-in 的 `placement: 'cursor' | 'auto' | 'above'` 和 `maxHeight`，默认行为不变。
- 测量菜单真实高度；下方放不下时向上翻转，并设置可用最大高度与内部滚动。
- `AddNodeMenu` 删除 `translateY(-100%)` 和整屏 `calc(100vh-120px)`：
  - 底部工具条用 `above`；
  - 双击、拉线、节点 `+` 用 `auto`。
- 滚动区加 `overscroll-contain`。

**验收**

- 在窗口底部打开“添加节点”时向上展开且可滚动；
- 搜索过滤后高度变化不跳动；
- 现有右键菜单、节点菜单行为不变。

### 3.4 纯素材节点隐藏提示词栏

**现状**

- `PromptBar` 只根据 `data.assetOnly` 隐藏。
- 只有 PromptBar 上传、CineBot 上传、Agent 资产库节点写入了 `assetOnly`。
- 拖拽上传、素材库插入、导入素材、`addAssetNodes` 批量插入都没有写，因此仍显示提示词栏。

**方案**

- 在缺失入口补 `assetOnly: true`：
  - `Canvas.tsx` 拖拽上传；
  - `LibraryWindow.tsx` 素材库“添加到画布”；
  - `context-actions.ts` 导入素材；
  - `addAssetNodes` 增加可选参数，拉片/剪辑室插入纯素材时传入。
- 旧项目兜底：单结果、`model` 为 `本地上传` 或 `资产库`、且无 prompt 的节点视为素材节点。
- 生成历史插入的节点不标记，保留继续生成能力。

**关于“用此素材生成”**

上传素材节点隐藏提示词栏后，需要保留生成入口，否则用户会失去用素材做图生图/参考生成的能力。方案如下：

- 生成入口统一走素材节点右侧的 source handle：点开 `+` 菜单或拉线创建下游节点，提示词栏出现在新节点上。
- 不新增「用此素材生成」按钮；原素材节点保持素材语义。
- 节点工具栏已有的生成操作（九宫格、角色四视图、多角度等）继续可用，这些操作会把当前素材作为输入。

**验收**

- 拖拽、素材库、导入素材创建的图片/视频/音频节点不再显示提示词栏；
- 生成结果节点和生成历史节点不受影响；
- 素材节点可通过右侧 `+` 创建下游节点继续生成。

### 3.5 上传素材节点尺寸自适应

**现状**

- 拖拽、粘贴、生成结果、切换版本会按宽高比调整高度。
- PromptBar 上传、素材库插入、导入素材不读宽高，保持默认 `360 × 376`，图片 `object-contain` 后出现留白。
- `LibraryAsset` 没有 `width/height`。

**方案**

- 抽取 `fitNodeHeightToMedia(nodeId, width, height)`：
  - 宽度保持当前节点宽度；
  - 高度按素材比例计算并加 `TITLE_HEIGHT`；
  - 高度做合理 clamp；
  - 分组内节点同步 `syncGroupBounds`。
- 在 PromptBar 上传、素材库插入、导入素材三个入口先 `window.api.media.probe(path)`，失败时回退图片 `naturalWidth/naturalHeight`。
- 中期可选：`LibraryAsset` 增加 `width/height`，素材库列表直接带尺寸。

**验收**

- 上传 1:1、16:9、9:16 图片，节点边框比例贴合、无大块留白；
- 视频同样生效；
- 分组边框跟随。

**说明**

当前自动适配只改高度、不改宽度。若要求“节点宽度也完全按图片像素贴合”，需要允许修改节点宽度，会联动分组、对齐和 PromptBar 定位，建议后续单独评估。

### 3.6 节点两侧加号可见性

**现状**

- `src/renderer/src/styles/infrastructure.css` 中加号圆点使用 `--surface` 背景、1px `--border` 边线、`--text-2` 图标。
- 只在节点 hover 或选中时显示，整体对比度偏低。

**方案**

- 提高图标颜色到 `--text-1`。
- 外圈边线改为更明显的 `--border-strong`，线宽 1.5px，增加轻微投影。
- 在加号图标外围增加一圈细边线（内圈），与外圈形成双层圆环。
- 保持 hover / 选中显示逻辑不变，避免所有节点同时出现大量圆点。

**验收**

- 选中节点时左右加号清晰可辨；
- hover 时颜色和边线进一步增强；
- 不影响连线拖拽热区。

### 3.7 快捷键自定义

**现状**

- 快捷键硬编码在 `Canvas.tsx`、`App.tsx`、`StudioWindow.tsx`、`TimelinePane.tsx`、`StageWindow.tsx` 等监听中。
- 设置页“快捷键”只有占位文案，没有 keymap 或持久化结构。
- 静态快捷键浮窗与真实实现已经漂移。

**方案**

- 新增 `src/shared/shortcuts.ts` 动作注册表，定义动作、分组、作用域、默认键。
- `Preferences.shortcuts.bindings` 只保存覆盖项，默认值从注册表读取。
- 新增 `useAppShortcuts` 匹配器和 `ShortcutRecorder` 录制控件：
  - 忽略输入框、`contenteditable`、输入法组合态；
  - 同作用域冲突检测，跨作用域允许同键；
  - 单行恢复默认与全部恢复默认；
  - 不支持录入 `Esc`、`Tab` 和仅修饰键。
- 替换应用、画布、剪辑室、导演台的硬编码监听；`Esc`、`Enter`、弹窗方向键等固定行为保留。
- `ShortcutPanel`、右键菜单、按钮 label 统一从注册表生成。
- macOS 原生菜单的 `undo/redo/copy/paste` role 需要同步处理，避免抢占自定义按键。

**验收**

- 修改“撤销”为 `Ctrl+Alt+Z` 后立即生效并重启保留；
- 冲突有提示；
- 恢复默认可用；
- 输入框、设置页、弹窗打开时画布快捷键不触发；
- macOS 显示 `⌘`。

### 3.8 技能页卡片化

**现状**

- 设置页“技能”是左栏列表 + 右侧编辑器。
- `canvas-basics` 是内置默认技能，靠目录判断 `builtin`。
- `skills:read-file` 已能读取 `SKILL.md` 正文，`Dialog` 与 `renderMarkdown` 可复用。

**方案**

- 共享常量标记默认技能 `canvas-basics`，设置页默认过滤；提供“显示内置技能”开关。
- 默认视图改为卡片网格：名称、作用域、描述、版本、启用状态、被覆盖状态。
- 点击卡片打开 `Dialog`，读取并渲染 `SKILL.md` 正文；footer 提供「打开目录」「编辑技能」。
- 保留现有详情编辑器作为编辑视图，新建/保存/删除/覆盖逻辑不动。

**验收**

- 默认 `canvas-basics` 不显示；
- 自定义技能以卡片展示；
- 点击卡片看到 Markdown 正文；
- 编辑、新建、启用/禁用仍正常。

**已知限制**

技能正文中的相对图片暂不渲染，预览中会注明。

### 3.10 图片节点默认功能栏

**现状**

图片节点默认只有「宫格切分、裁剪」，常用生成和编辑操作都藏在「更多」里。

**方案**

- 默认显示：宫格切分、裁剪、九宫格、打光、扩图、抠图、反推提示词。
- `MAX_PRIMARY` 从 6 调到 7。
- 角色四视图、画面推演、多角度、720 全景、人像质感、重绘、擦除、图层分离保留在「更多」。

**验收**

选中图片节点后，7 个默认按钮直接可见，其余操作仍可从「更多」进入。

### 3.11 反推提示词

**现状**

图片节点没有把画面分析结果转成可复用提示词的入口。

**方案**

- 新增图片操作 `reverse-prompt`，默认提示词固定为九维拆解文案。
- 弹窗参考打光：选择模型 + 可编辑提示词。
- 模型只列支持图片输入的 `text.chat` 模型。
- 确认后创建文本节点、自动连线，并把源图片作为参考输入；生成结果写入文本节点。

**验收**

没有可用文本视觉模型时引导去设置；有模型时生成文本节点并显示反推结果，连线正确。

### 3.12 多行输入固定高度

**现状**

共享 `Textarea` 默认 `resize-y`，打光弹窗等输入框可以拖拽调整高度。

**方案**

- `Textarea` 统一改为 `resize-none overflow-y-auto`。
- 移除业务组件里的 `resize-y`。
- 所有多行输入固定高度，内容超出时内部滚动。

**验收**

打光、技能编辑、模板、剪辑室检查器等输入框不再出现拖拽手柄，长文本可上下滚动。

### 3.13 操作提示词保存

**现状**

打光等操作的提示词来自代码常量，用户修改后关闭弹窗即丢失。

**方案**

- `Preferences.operationPrompts` 保存覆盖项，键为 `操作ID:菜单项ID`。
- 每个操作/菜单项只保留一个版本，重复保存覆盖。
- 弹窗提供「保存」和「恢复默认」；恢复默认删除覆盖项。
- 随 `preferences.json` 导出/导入，重启后保留。

**验收**

修改打光「顶光」提示词并保存，重新打开仍显示自定义内容；恢复默认回到代码文案。

### 3.14 设置页信息架构

**现状**

- 设置页有 9 个 tab；`GeneralSettingsSection` 一个页面包含 8 组内容。
- 默认模型与“模型服务”重复，更新偏好与“关于”重复，界面缩放与“外观”重复。
- MCP 没有设置入口。

**目标分组**

| 分组 | 内容 |
|---|---|
| 通用 | 启动时打开最近项目、自动保存间隔、关闭前确认、默认项目目录、生成完成通知 |
| 外观与画布 | 主题、界面缩放、减少动效、网格样式、显示连线、小地图、网格吸附、滚轮行为、双击缩放 |
| 创作与生成 | 默认模型、并发数、AutoLink、失败重试、AI 水印、生成历史保留、场景物体类别 |
| 模型与运行时 | 供应商/模型、本地适配器、本地组件、模型接入指南、代理与超时、`models.json` 高级 |
| 技能 | 技能卡片、Markdown 预览、新建/编辑；MCP 状态与配置待后续 |
| 资产与存储 | 全局资产库、缩略图缓存、自动清理、生成历史清空、数据目录、备份/导入/重置 |
| 快捷键 | 应用/画布/剪辑室/导演台分组、搜索、录制、冲突提示、恢复默认 |
| 关于与更新 | 版本、仓库、协议、更新通道、检查/下载/安装、日志目录 |

**实现要点**

- 保留现有 `SectionId` 作为内部路由 key，合并 tab 时加别名，避免深链接失效。
- 拆分 `GeneralSettingsSection`；外观统一走 `useTheme`。
- “重置通用设置”与“重置快捷键”拆开。
- MCP 设置需要新增状态/配置 IPC，建议 P3。

- 已知限制：macOS 原生菜单的 `undo/redo/copy/paste` role 仍可能占用 Cmd 组合键，后续需要重建应用菜单。

### P3 进展

- 设置页收为 8 个分区：通用、外观与画布、创作与生成、模型与运行时、技能、资产与存储、快捷键、关于与更新。
- 启动/通知留在通用；画布/界面/主题合并到外观与画布；默认模型与生成行为合并到创作与生成；组件/网络合并到模型与运行时；资产库与缓存/备份合并到资产与存储；更新偏好合并到关于与更新。
- 旧深链接 `library`、`components`、`objectPresets` 自动映射到新分区。
- 快捷键和技能卡片沿用 P2/P1b 的独立分组。
- 修复快捷键页搜索框撑满导致的标题竖排与横向滚动。
- 开关统一为长方形轨道 + 正方形滑块，两侧间距对称；生成并发默认 8；删除仅有的稳定版/测试版更新通道选择。
- MCP 设置入口仍为后续项；当前只保留技能分组。

## 5. 风险与非目标

- 节点尺寸自动适配不改变宽度；真正的“按像素贴合”需要改宽度和分组布局，另案评估。
- 素材节点隐藏提示词栏后，生成入口必须保留；P1 之前先用现有工具栏生成操作兜底。
- 快捷键改造涉及全局监听和 macOS 原生菜单，必须单独回归。
- 设置页重组以迁移为主，不新增业务能力。
- 技能正文相对图片、MCP 设置界面属于后续项，不在 P0。
