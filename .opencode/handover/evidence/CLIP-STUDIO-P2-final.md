# CLIP-STUDIO P2 收尾：4K、流式帧、取消、长片稳定

日期：2026-11-07
状态：完成
验证：typecheck / 57 测试 / build 通过；4K、30 秒、3 分钟、取消、预览一致性均有实测

## 1. 帧流式写入

- 完整路径不再写临时 JPEG 序列，改为单个 ffmpeg 进程：
  `-f image2pipe -framerate fps -i -`。
- 主进程逐帧 `executeJavaScript` 取 JPEG data URL，转 Buffer 写入 ffmpeg stdin，带 backpressure。
- 音频仍作为后续 `-i` 文件输入，filter 索引从 1 开始。
- 移除 `app.getPath('temp')` 帧目录与 `randomUUID`。
- 导出结束/取消/失败后没有 `cinelab-export-*` 临时目录。

## 2. 取消与清理

- `timeline:export` 返回 `{ ok, path } | { ok: false, canceled: true }`。
- 新增 `timeline:export-cancel`，主进程维护单个 `AbortController`。
- 渲染循环每帧检查 aborted；ffmpeg 使用 `SIGKILL`。
- `runFfmpeg` 和流式 ffmpeg 都改为**等待子进程真正退出后再 reject**，避免 Windows 上文件仍被占用导致删除失败。
- 取消后删除半成品 mp4；三条路径均验证无残留。

UI：

- 导出中按钮变为「取消生成 N%」，编码阶段显示「编码中… 取消」。
- 取消结果 toast「已取消导出」，成功 toast「成片已生成：路径」。

## 3. 快速路径分层

新增 `src/main/timeline/stream-copy.ts`：

1. **stream-copy（新增，最快）**
   - 单视频轨、首尾相接、源片段不裁剪（`sourceStartMs === 0`）。
   - 无变速/变换/裁剪/转场/文字/关键帧。
   - 音量为 1、无淡入淡出、未静音。
   - 所有源的分辨率、帧率、视频编码、像素格式一致，且与时间线输出一致。
   - 音频编码、采样率、声道数一致；要么都有音轨，要么都无音轨。
   - 满足时 `concat` demuxer + `-c copy`，不重新编码。
2. **编码快速路径（原有）**：不满足 stream-copy 时 `trim/scale/pad/concat` 重新编码。
3. **逐帧完整路径**：多轨、文字、变速、效果等回退。

源片段时长与时间线片段时长允许 150ms 误差，因此 stream-copy 输出可能比时间线长最多约 0.2 秒。

## 4. 实测数据

### 4K 逐帧导出

| 项 | 结果 |
|---|---|
| 输入 | 3840×2160 / 24fps / 4 秒 / 带 AAC |
| 输出 | 3840×2160 / 120 帧 / 4.000 秒 / AAC |
| 耗时 | 第 1 次 26.2 秒；第 2 次 24.4 秒 |
| 文件 | 2.7–3.4MB |
| Electron 内存 | 基线 740MB → 峰值 1656MB → 结束 890MB |
| 连续第二次 4K | 基线 890MB → 峰值 1679MB → 结束 889MB |

两次 4K 导出结束内存基本一致，没有持续增长。

### 30 秒 1080p 逐帧

| 项 | 结果 |
|---|---|
| 输出 | 1920×1080 / 900 帧 / 30.000 秒 / AAC |
| 耗时 | 39.9 秒 |
| 文件 | 11.8MB |
| Electron 内存 | 828MB → 峰值 1138MB → 结束 828.7MB |

### 3 分钟纯拼接

| 路径 | 结果 |
|---|---|
| stream-copy | 1728×992 / 24fps / 180.198 秒 / 4323 帧 / **3.47 秒**（0.019× 片长） |
| 编码快速路径（1920×1080 30fps） | 180.000 秒 / 5400 帧 / 68MB / 144 秒（0.8× 片长） |

stream-copy 满足方案「纯拼接耗时不高于片长 0.2 倍」的验收。

### 取消

| 场景 | 结果 |
|---|---|
| 逐帧路径 1.5 秒取消 | `{ok:false,canceled:true}`，1.54 秒返回，无新文件 |
| 逐帧路径 8 秒取消 | 8.05 秒返回，无半成品 |
| stream-copy 1 秒取消 | 1.21 秒返回，无半成品 |
| 编码快速路径 2 秒取消 | 2.16 秒返回，无半成品（修复前会残留 1 个文件） |
| UI 取消 | 按钮恢复「生成成片」，toast「已取消导出」 |
| 临时目录 | 全程无 `cinelab-export-*` |

## 5. 预览与导出一致性

- 同一渲染器 `renderTimeline` 同时服务预览和导出。
- 视频预览默认使用 540p 代理，与原片导出做像素比对没有意义。
- 用 1920×1080 静态图片片段在 1 秒处对比：
  - 预览 canvas PNG vs 导出视频抽帧 PNG
  - PSNR average **39.16dB**（R 34.77 / G 41.28 / B 41.10）
  - 差异主要来自导出 JPEG 0.92 压缩。

## 6. 已知限制

- stream-copy 允许单片段 150ms 时长误差，长片尾帧可能多出约 0.2 秒。
- stream-copy 只覆盖单视频轨、无裁剪、无变速、无文字、无独立音频轨的纯拼接。
- 4K 逐帧导出约为实时 6 倍耗时；更长 4K 片会线性增长。
- 取消 kill 后最多等待 5 秒兜底；正常情况立即退出。
- 多窗口并行导出仍未做，留待 POC 决策。
