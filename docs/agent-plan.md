# 剪辑室智能编排与内置 Agent 方案

日期：2026-11-08
状态：阶段 1-3 已完成（2026-11-08）；剪辑助手已用通用 AgentRuntime 以 `clip` profile 重建（2026-11-09）；阶段 4 待开始
范围：剪辑室自动粗剪、对话式剪辑、内置创作 Agent

## 1. 结论

- 剪辑室作为手工剪辑工具已经完成，不需要重做基础能力。
- 本文只规划「自动编排」：规则式自动粗剪 + 对话式剪辑（内置 Agent）。
- 两者分层开发、共用工具层：
  - 规则式先做，不依赖模型，独立可用、独立验证。
  - 对话式后做，是 Agent 的交互入口，调用同一套工具。
- 本期不做外部 Agent / MCP / CLI 接入；内置 Agent 跑通后再评估。

## 2. 两层能力

### 2.1 规则式自动粗剪

用户点按钮，执行确定性操作：

- 一键删静音
- 按镜头切分
- 按节拍卡点
- 批量生成字幕（已有能力，接入统一入口）

特点：不接大模型、结果可预测、可单测、可端到端验证。

### 2.2 对话式剪辑（内置 Agent）

用户用自然语言描述意图，Agent 理解、规划、调用工具、给出方案：

- 「删掉所有静音」
- 「按镜头切开，每个镜头保留前半段」
- 「跟着这首音乐的节拍卡点」
- 「把这段访谈剪成 1 分钟」

特点：需要模型、需要上下文、需要方案预览与确认，但执行仍走同一套工具和命令层。

## 3. 总体架构

```
┌─────────────────────────────────────────────┐
│ 剪辑室 UI                                    │
│  检查器「自动粗剪」按钮    右侧「助手」面板    │
└───────────────┬─────────────────────────────┘
                │
┌───────────────▼─────────────────────────────┐
│ 编排层                                       │
│  规则编排（固定顺序）   Agent 编排（模型规划） │
└───────────────┬─────────────────────────────┘
                │  统一工具协议
┌───────────────▼─────────────────────────────┐
│ 工具层                                       │
│  analyze_silence / analyze_shots / analyze_beats │
│  transcribe / plan_remove_ranges / plan_split     │
│  plan_add_subtitles / plan_markers                 │
└───────────────┬─────────────────────────────┘
                │
┌───────────────▼─────────────────────────────┐
│ 现有能力                                     │
│  timeline-commands / timeline-edit           │
│  主进程分析 IPC / whisper / ffmpeg            │
└─────────────────────────────────────────────┘
```

关键原则：

- 工具只产出「计划」：只读分析和 `TimelineCommand[]`，不直接改文档。
- 用户确认后，计划作为一条 `batch` 命令提交，只占一条撤销记录。
- 规则按钮和 Agent 调用完全相同的工具，避免两套逻辑。
- 模型请求走主进程，渲染进程不直接访问外部 API，符合项目硬性约定。

### 3.1 Agent 运行时与场景配置分离

剪辑助手和后续的画布助手共用一套底层框架，但不是同一个助手，也不共用对话。

| 层 | 剪辑助手 | 画布助手（后续） |
|---|---|---|
| 模型接入 / 工具循环 / 取消重试 | 共用 | 共用 |
| 对话 UI 组件 | 共用 | 共用 |
| 系统提示 | 剪辑导演 | 创作助理 |
| 上下文 | 时间线、选中片段、素材 | 画布节点、连线、选中、资产 |
| 工具白名单 | 时间线域 | 画布域 |
| 撤销域 | timeline history | canvas history |
| 对话实例 | 独立 | 独立 |

- `AgentRuntime`：负责模型请求、工具调用循环、结果回填、取消与超时。
- `AgentProfile`：每个场景一份配置，包含系统提示、工具白名单、上下文构建器和确认策略。
- `ToolRegistry`：工具统一注册，按 profile 过滤，Agent 只能看到白名单内的工具。
- 三个隔离：对话隔离、上下文隔离、撤销隔离。剪辑助手不能直接改画布结构，画布助手不能直接改时间线。
- 跨域操作（例如画布助手把生成结果放进剪辑室）必须通过显式工具并二次确认，不能默认混在一起。
- 本期只实现剪辑助手；运行时按可扩展方式设计，画布助手后续只增加 profile 和工具，不重写运行时。

## 4. 阶段 1：规则式粗剪 + 工具层

### 4.1 工具清单

| 工具 | 输入 | 输出 | 实现落点 |
|---|---|---|---|
| `analyze_silence` | clipId 或整条时间线 | 静音区间（时间线毫秒） | 复用 `analysis.ts` silencedetect |
| `analyze_shots` | clipId | 镜头切点（时间线毫秒） | 复用 `analysis.ts` scdet |
| `analyze_beats` | clipId | 节拍点（时间线毫秒） | 复用 `analysis.ts` 能量峰值 |
| `plan_remove_ranges` | 区间、padding、联动选项 | `TimelineCommand[]` | `splitClips` + `removeClips` + `closeGaps` |
| `plan_split_at` | 切点数组 | `TimelineCommand[]` | `splitClips` |
| `plan_align_beats` | 节拍点、模式 | `TimelineCommand[]` | 切分 / 加转场 / 加 marker |
| `plan_subtitles` | 转写结果、轨道 | `TimelineCommand[]` | `addClips` |
| `plan_markers` | 分析结果 | `TimelineCommand[]` | `addMarker` |

工具统一返回：

```ts
interface TimelinePlan {
  title: string
  summary: string
  commands: TimelineCommand[]
  warnings: string[]
}
```

### 4.2 一键删静音

参数：

- `minDurationMs`：默认 400ms，短于该值不处理
- `paddingMs`：默认 120ms，静音两端保留，避免切掉呼吸声
- `scope`：选中片段 / 整条时间线
- `linkage`：是否联动删除依附的字幕/音频片段，默认跟随 `doc.linkage`

执行：

1. 调用静音检测，得到区间。
2. 两端各收缩 `paddingMs`，过滤过短区间。
3. 对每个区间生成 `splitClips`，再生成 `removeClips`。
4. 主轨使用 ripple 删除，闭合空隙；其他轨按 linkage 处理。
5. 所有命令打包成一条 `batch`，label「自动粗剪 · 删静音」。

安全：

- 删除前在时间线显示预览高亮（可选，阶段 2 再做）。
- 操作后立即可以 Ctrl+Z 完整恢复。

验收：

- 10 秒含 3 段静音的素材，执行后时长减少符合预期。
- 字幕/音频依附片段跟随移动，不错位。
- 一条撤销恢复原时间线。

### 4.3 按镜头切分

参数：

- `minShotMs`：默认 500ms，过短镜头不切
- `scope`：选中视频片段 / 主轨全部

执行：

1. 对片段调用 `scdet`，得到相对片段的切点。
2. 按 `speed` 和 `sourceStartMs` 映射到时间线。
3. 过滤片段首尾 100ms 内的切点。
4. 批量 `splitClips`。
5. 一条撤销。

验收：

- 2 秒红 + 2 秒蓝测试视频在 2 秒处切成两段。
- 变速片段切点位置正确。
- 切割后片段内容与切点前后帧一致。

### 4.4 按节拍卡点

参数：

- `clipId`：音频或视频片段
- `mode`：`markers` / `split` / `transition`
- `minGapMs`：默认 250ms

执行：

- `markers`：把节拍点写成 marker，供手动对齐。
- `split`：在主轨片段对应位置切分。
- `transition`：在切点两侧片段加短转场（默认 200ms）。

验收：

- 节拍 marker 与音频峰值对齐，误差不超过 50ms。
- `split` 后切点与节拍点一致。
- `transition` 不产生重叠或黑帧。

### 4.5 UI 入口

在检查器「AI 分析」区下方新增「自动粗剪」区：

- 删静音
- 按镜头切分
- 按节拍卡点

未选中片段时作用于整条主轨；选中片段时只作用于该片段。

每个按钮执行前显示一行说明和预计影响（例如「将删除 7 段静音，约 42 秒」），确认后执行。

### 4.6 撤销与预览

- 所有规则操作只产生一条 `batch` 撤销记录。
- 执行后 toast 显示「已删除 7 段静音，时长 10:00 → 08:42」。
- 暂不做执行前画面预览，阶段 2 与 Agent 共用方案预览。

## 5. 阶段 2：对话式剪辑 MVP

### 5.1 界面

剪辑助手的主入口是剪辑室右侧检查器，顶部增加两个页签：

- 「属性」：现有 InspectorPane
- 「助手」：对话面板

本期**不使用画布剪辑室节点上的 prompt 输入框**作为 Agent 入口。原因是多轮对话、方案确认、选中片段上下文和预览都需要在剪辑室内完成；节点上的单次输入框无法承载这些交互。后续如有需要，可以把它作为「快捷指令」入口，复用同一套 Agent 工具，但不作为本期范围。

对话面板包含：

- 消息列表（用户 / 助手）
- 输入框和发送按钮
- 「停止」按钮
- 方案确认卡片：摘要 + 影响 + 「应用」/「取消」

### 5.2 运行位置

- 工具执行与上下文构建在渲染进程：时间线文档和 store 都在这里。
- 模型请求在主进程：新增 `agent:chat` IPC，读取 `models.json` 的 `text.chat` 模型并调用 provider。
- 渲染进程只拿到模型回复，不接触 API Key。

### 5.3 模型协议（MVP）

为兼容中转站，MVP 不依赖原生 function calling，使用结构化 JSON 计划：

```ts
interface AgentPlan {
  reply: string
  intent: 'remove_silence' | 'split_by_shots' | 'align_beats' | 'auto_subtitles' | 'answer' | 'unsupported'
  args: Record<string, unknown>
  needsConfirm: boolean
}
```

流程：

1. 渲染进程构建上下文：项目名、时间线摘要、选中片段、素材清单、可用工具说明。
2. 调用 `agent:chat`，要求模型只输出 JSON。
3. 解析并校验；失败时让模型重试一次，仍失败则提示。
4. 根据 `intent` 调用对应工具生成 `TimelinePlan`。
5. 展示回复与方案卡片。
6. 用户点「应用」后，把 `commands` 作为 `batch` 提交。

MVP 只支持单轮计划和少量意图，不做自由工具循环。

### 5.4 上下文

只发送必要信息，避免长上下文和隐私问题：

- 项目名、时间线时长、轨道数、片段数
- 选中片段的 id、类型、起点、时长、名称、是否有音轨
- 素材清单的名称、类型、时长
- 最近 6 条对话消息

不发送：完整时间线 JSON、文件绝对路径、API Key、素材内容。

### 5.5 方案预览与确认

- 应用前用 `applyCommands(doc, commands)` 计算预览文档，不写入 store。
- 显示：命令数量、删除/新增片段数、总时长变化、警告。
- 用户确认后 dispatch 一条 `batch`。
- 用户取消则丢弃计划，不产生撤销记录。

### 5.6 撤销与审计

- 每轮应用 = 一条撤销记录，label 带用户意图。
- 分析类只读操作不产生撤销记录。
- 生成历史可选记录 Agent 操作（阶段 3）。

### 5.7 错误与取消

- 模型未配置：提示去设置配置 `text.chat` 模型。
- 模型返回非 JSON：自动重试一次，仍失败显示原文并提示重试。
- 用户点停止：中止主进程请求，丢弃未完成计划。
- 工具执行失败：不修改文档，显示错误。
- 模型超时：默认 60 秒，可在设置中调整。

### 5.8 验收

- 「删掉所有静音」生成正确方案并应用。
- 「按镜头切开」生成正确切点。
- 用户取消不修改时间线。
- 应用后一条 Ctrl+Z 完整恢复。
- 模型未配置时有明确引导。
- 断网/超时有可读错误，不卡死 UI。

## 6. 阶段 3：多轮与修改

- 支持「再紧凑一点」「这段不要」「字幕提前半秒」。
- 引入工具执行结果回填，模型可基于结果继续规划。
- 方案 diff：显示将删除/保留的片段列表。
- 对话历史仅保存在当前剪辑室会话，不落盘。
- 可选：把 Agent 操作写入项目日志，便于排查。

## 7. 阶段 4：高级编排

在阶段 1-3 稳定后逐项接入：

- 分镜组一键成片：读取分镜组顺序和时长，生成完整时间线。
- 文案成片：文案分段 → 匹配素材/生成旁白 → 字幕与画面。
- 音乐卡点：整条音乐分析 → 片段切点/转场批量对齐。
- 多版本方案：一次生成 2-3 个剪辑方案供选择。

每项都先落独立方案文档，再进入实现。

## 8. 数据结构与 IPC

新增 `src/shared/agent.ts`：

```ts
type AgentProfileId = 'clip' | 'canvas'

type AgentToolId =
  | 'analyze_silence'
  | 'analyze_shots'
  | 'analyze_beats'
  | 'plan_remove_ranges'
  | 'plan_split_at'
  | 'plan_align_beats'
  | 'plan_subtitles'

interface AgentChatRequest {
  modelId: string
  profileId: AgentProfileId
  messages: { role: 'user' | 'assistant'; content: string }[]
  context: AgentContext
}

interface AgentChatResult {
  content: string
}
```

场景配置放主进程，渲染进程只传 `profileId`，不能自定义系统提示：

```ts
interface AgentProfile {
  id: AgentProfileId
  systemPrompt: string
  tools: AgentToolId[]
  /** 需要用户确认的工具或意图 */
  confirmBeforeApply: boolean
}
```

本期只注册 `clip` profile；`canvas` 先留空，后续补工具。

IPC：

- `agent:chat`：主进程按 `profileId` 选择系统提示和工具白名单，调用 `text.chat` 模型，返回文本。
- `agent:cancel`：中止当前请求。
- 复用现有 `timeline:analyze`、`timeline:transcribe`，不重复造分析接口。

模型选择：

- 从 `models.json` 读取 `capability === 'text.chat'` 的模型。
- 多个时优先用户在设置中选择的默认模型；未选择则取第一个。
- 无可用模型时，助手面板显示配置引导。

## 9. 安全与边界

- 只操作当前打开项目的时间线，不读写项目外文件。
- 不删除、不移动素材文件，只改时间线引用。
- 导出、删除轨道等高风险操作必须二次确认。
- 每轮操作可撤销；失败不修改文档。
- 不把 API Key、绝对路径、完整文档发送给模型。
- Agent 不执行任意代码，只能调用白名单工具。
- 外部 Agent / MCP 接入不在本期范围，避免权限边界复杂化。

## 10. 明确不做

- 通用编码 Agent。
- 外部 Agent / MCP / CLI 接入（本期）。
- 画布助手（本期只做运行时预留，不实现画布域工具）。
- 画布剪辑室节点上的 prompt 输入框入口（本期）。
- 多轮无限上下文与长期记忆。
- 自动删除素材文件。
- 全自动导出并覆盖成片（导出仍需用户确认）。

## 12. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 中转站不支持稳定 JSON 输出 | Agent 解析失败 | 结构化输出 + 重试 + 明确错误提示；必要时改用原生 function calling |
| 静音检测误判 | 删掉有效语音 | 默认保留 padding、可调阈值、执行前显示影响、随时撤销 |
| 镜头检测切点偏差 | 画面切到一半 | 过滤首尾、允许最小镜头时长、应用前预览切点 |
| 节拍检测多检/漏检 | 卡点不准 | 先提供 marker 模式，用户可手动调整后再切 |
| 长对话上下文膨胀 | 成本与延迟 | 只发摘要和最近消息，阶段 3 再做压缩 |
| Agent 误操作 | 数据损坏 | 白名单工具、方案确认、一条撤销、失败不落盘 |
