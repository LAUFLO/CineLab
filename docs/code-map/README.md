## 阅读顺序

出方案前：

1. 读本页，定位 1–3 个模块；
2. 读 [08 能力清单](08-capabilities.md) 中相关行；
3. 读对应模块文档的「速查区」「当前状态」「已知限制」；
4. 需要接口/文件清单时读 [_generated](_generated.md)；
5. 方案必须写：**现状 / 改动点 / 影响模块 / 验收**。

实施后：

1. 更新对应模块的「当前状态」与「证据」；
2. 若新增/删除文件，运行 `corepack pnpm map:code`；
3. 运行 `corepack pnpm check:docs`。

## 维护约定

- `<!-- AUTO:files:start --> … <!-- AUTO:files:end -->` 与 `<!-- AUTO:exports:start --> … <!-- AUTO:exports:end -->` 由脚本维护，**不要手工改**。
- 人工只维护：职责、入口、数据流、当前状态、已知限制、下一步。
- 模块可重叠引用，但规模统计只按互斥归属，避免重复计数。
- 新增模块：在 `scripts/gen-code-map.mjs` 的 `MODULES` 中登记，并创建对应文档。
- 文档状态只允许三档：**已实现 / 部分实现 / 仅文档**。
