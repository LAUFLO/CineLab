# 工具栏占位功能补齐方案

日期：2026-11-07
状态：实施中（批次 1）
关联：`docs/node-toolbar-plan.md`、`docs/runtime-components-plan.md`

## 1. 背景

节点工具栏「更多」中仍有 13 个入口只显示「正在接入」或禁用提示，用户无法判断是未开发、缺模型还是缺组件。本方案把全部入口补齐，分四批交付，每批都要求入口状态明确、可用路径可走通。

范围只包含工具栏占位入口，不含已移除的高清/超分、剪辑台、Agent。

## 2. 状态模型

不再使用单一的 `implemented: false` 表示占位。每个操作必须声明以下状态之一：

| 状态 | 含义 | UI 行为 |
|---|---|---|
| `ready` | 已实现 | 直接执行 |
| `needs-model` | 需要用户配置对应模型 | 点击提示并打开模型设置 |
| `needs-component` | 需要安装本地视觉组件 | 点击提示并打开组件设置 |
| `unsupported` | 当前素材不支持 | 禁用并说明原因 |

实现上以可选字段表达，保持向后兼容：

```ts
interface NodeOperation {
  implemented?: boolean
  requires?: {
    type: 'image-model' | 'video-model' | 'video-edit-model' | 'vision-component'
    label: string
    panel?: 'models' | 'components'
  }
}
```

## 3. 四批交付

### 批次 1：图片编辑与全景

| 功能 | 实现 |
|---|---|
| 重绘 | 蒙版编辑器 + 提示词 → 图片模型 `/images/edits` 的 `mask` 字段 |
| 擦除 | 蒙版编辑器 + 固定提示词「移除选区并补全背景」 |
| 元素编辑 | 蒙版编辑器（框选/画笔）+ 用户描述，局部重绘 |
| 扩图 | 批次 1 先走图片模型 + 结构化提示词；批次 2 增加扩展画布与 LaMa 兜底 |
| 720 度全景图 | 图片模型生成 2:1 等距柱状图；内置 3D 全景查看器（three） |
| 状态改造 | 其余未完成入口改为「需配置模型 / 需安装组件」，不再出现「正在接入」 |

蒙版格式：

- 前端输出 PNG data URL，透明区域表示需要编辑，其余区域为不透明白色。
- `GenerateRequest` 增加可选 `mask` 字段；主进程直接传给 `generateImage`。
- 仅对 `image.i2i` / `image.t2i` 生效；不支持 mask 的适配器返回明确错误。
- 结果仍作为当前节点新版本，不覆盖原图。

全景查看器：

- 生成时 `GenerateRequest.op = 'panorama'`，`OutputRef.op` 记录来源。
- 图片预览层出现「全景」按钮；查看器使用球体内视、拖拽旋转、滚轮缩放、ESC 退出。
- 不要求生成图严格 2:1，比例不符时提示可能拉伸。

### 批次 2：本地视觉 runtime

| 功能 | 实现 |
|---|---|
| 抠图 | RVM 输出透明前景 PNG；组件未安装时回退到图片模型提示词抠图 |
| 图层分离 | RVM 前景 PNG + LaMa 背景修复，输出两个图层节点 |
| 视频智能抠像 | RVM 输出带 alpha 的 WebM，限制 480P / 10 秒 |
| 智能去字幕 | 框选字幕区域 + LaMa 逐帧修复 |
| 主体消除 | 框选主体 + LaMa 逐帧修复 |
| 扩图 | 选择目标比例，LaMa 扩展画布并补全边缘 |

组件复用 `depth-runtime` 的 Python/PyTorch 环境：

- `vision-models`：RVM 权重 + LaMa 权重 + worker + torchvision/Pillow，约 213MB 压缩 / 241MB 解压。
- 不新增独立 runtime，避免重复下载约 1GB 的 PyTorch。
- worker 通过 stdout JSON 行上报进度，主进程沿用 `depth-tasks` 的任务/取消模式。

限制：

- 视频修复与抠像只支持短片（默认 ≤10 秒），超限直接拒绝并提示。
- 视频抠像输出 480P，CPU 推理耗时较长，必须显示进度并支持取消。
- RVM 为 GPL-3.0，组件内附 NOTICE；对外发布前需确认许可证合规。

### 批次 3：视频操作

| 功能 | 实现 |
|---|---|
| 片段重拍 | 优先专用视频编辑 API；未配置时用首帧 i2v 近似，明确提示「整段重生成」 |
| 元素替换 | 专用视频编辑 API；未配置时用首帧 i2v 近似并提示 |
| 智能续写 | 尾帧 i2v 生成后续片段，自动拼接；支持专用延长 API |
| 创意片头 | 内置片头模板 + 视频模型 |
| 视频参考 | `ReferenceInput` 支持 video / audio；HTTP 模板增加 `{{refs.video}}` / `{{refs.audio}}` |
| 操作模型绑定 | 设置页为每个操作指定模型或 HTTP 模板，未绑定则使用默认能力模型 |

### 批次 4：打包与验收

- 发布视觉组件 Release 与 manifest。
- CI 增加视觉组件构建、安装包构建。
- 真实素材验收：中文路径、竖屏、长视频、取消任务、旧项目兼容。
- 更新 `docs/node-toolbar-plan.md` 的决策记录。

## 4. 数据与接口变更

- `GenerateRequest`：新增 `mask?: string`、`op?: string`。
- `GeneratedAsset`：新增 `op?: string`，由主进程透传到 `OutputRef`。
- `ReferenceInput`：批次 3 扩展 `video` / `audio` 类型。
- 设置面板：新增 `components` 分区（已有），批次 3 新增操作模型绑定分区。
- 资产与画布数据结构保持向后兼容，旧项目无需迁移。

## 5. 验收标准

批次 1：

- 重绘、擦除、元素编辑能画笔/框选、能撤销、能提交并生成新版本。
- 生成失败时明确提示「当前模型不支持蒙版编辑」，不出现静默失败。
- 720 全景图生成后可进入查看器，拖拽、缩放、退出正常。
- 所有未完成入口显示具体依赖，不再出现「正在接入」。
- `pnpm typecheck` / `pnpm test` / `pnpm build` 通过。

实测记录（2026-11-07）：

- 蒙版编辑器画笔、矩形、橡皮、撤销、清空可用；「下一步」在涂抹后启用。
- 使用本地 mock `/images/edits` 服务验证：multipart 请求包含 `mask`，生成结果写入节点版本栈（3/3）。
- 修复全局资产作为参考图时未带 `scope` 导致参考图丢失的问题。
- 720 全景查看器可加载 2:1 测试图，拖拽、滚轮缩放、ESC 退出正常；自定义资产协议补充 CORS 头。
- 资产库添加的图片节点没有 `width/height`，全景入口改为按图片实际比例判断。

批次 2：

- 组件安装后，抠图、图层分离、视频抠像、智能去字幕、主体消除、本地扩图可用。
- 组件未安装时，抠图/扩图回退到图片模型提示词版，其余入口提示安装并跳转组件设置。
- 中文路径、空格路径、全局资产、取消任务、10 秒上限正常。
- worker 进度通过 `vision-task:event` 回传，失败时节点标红并显示原因。

实测记录（2026-11-07）：

- RVM 图片抠图 0.84 秒，图层分离 6.64 秒，LaMa 1:1 扩图 9.87 秒。
- 2 秒 720P 视频修复 73.55 秒，480P 视频抠像 5.53 秒，输出 WebM 带 `ALPHA_MODE=1`。
- 隔离实例本地 mock 组件源安装 `vision-models` 成功，组件 213MB / 解压 241MB / 332 文件。
- UI 实测：图层分离生成 2 个已完成节点；视频抠像生成 WebM 节点；本地扩图写入版本 2/2；本地抠图写入版本 3/3；智能去字幕、主体消除对话框标题正确。
- `pnpm typecheck` / `pnpm test` / `pnpm build` 通过。

批次 3–4 的验收在各自实施时补充。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 用户模型不支持 mask | 明确报错并提示换模型；批次 2 用本地 LaMa 兜底 |
| 全景图比例不标准 | 查看器兼容任意比例，UI 提示可能拉伸 |
| 视觉组件体积与 CPU 耗时 | 复用深度运行时，仅下载约 213MB 模型；视频限制 ≤10 秒、抠像 480P、显示进度与取消 |
| RVM GPL-3.0 许可证 | 组件内附 NOTICE 与来源；对外发布前确认合规或替换为宽松许可证模型 |
| 视频编辑 API 协议不统一 | 通过操作模型绑定 + HTTP 模板接入，不硬编码厂商 |
| 近似重生成误导用户 | 未配置专用 API 时强制二次确认，文案写明「整段重生成」 |
