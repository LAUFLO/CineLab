# CineLab 后续路线图

日期：2026-11-06
状态：待实施（按优先级逐步推进）

## 现状

- 画布、项目、模型接入、生成队列、资产库、分组/分镜、节点工具栏、导出、品牌与欢迎页均已完成
- `state.json` 仅剩两项未完成：
  - `DEPTH-CAPTURE-1`：深度动作捕捉收尾
  - `AGENT-1`：Agent 与画布协作
- 当前版本 `0.1.0`，尚无自动化测试、CI、自动更新和统一日志

## P0：发布前必须处理

### P0-1 安装包瘦身（ffprobe 全平台二进制）

**现状**

`ffprobe-static` 打包了 darwin / linux / win32 全平台二进制，`app.asar.unpacked` 中约 335MB，是安装包 225.6MB 的主要原因。

**动作**

- 打包前只保留 `node_modules/ffprobe-static/bin/win32/x64/ffprobe.exe`
- 或在 `electron-builder.yml` 的 `files` / `asarUnpack` 中排除其他平台目录
- 同步检查 `ffmpeg-static` 是否只有当前平台二进制

**验收**

- 安装包体积下降 60–80MB
- 打包态 `media:probe`、视频压缩、深度捕捉的 ffmpeg/ffprobe 路径正常
- `pnpm typecheck` / `pnpm build` 通过

**风险**

- 跨平台发布时需要恢复对应平台二进制；先用构建脚本按目标平台裁剪

### P0-2 深度动作捕捉收尾

**动作**

- 用真实拍摄素材验收：横屏、竖屏、运动幅度大、低照度各一段
- 走完整 UI 点击路径：视频节点 → 深度动作捕捉 → 参数 → 自动建节点/连线
- 在干净机器或 CI 上验证安装包内组件下载、Python runtime 启动、ffmpeg 编码

**验收**

- 输出比例与输入一致，灰度正确，无明显闪烁/拖影
- 组件下载、暂停、续传、卸载、未安装引导全部可用
- 打包态端到端通过

**依赖**

- 用户提供真实素材
- 打包机需绕开本机加密软件（见 P0-3）

### P0-3 GitHub Actions Windows 打包

**现状**

本机亿赛通加密软件会让 `app-builder.exe` 和 `CineLab.exe` 读到密文，导致 asar 损坏、安装后启动失败。当前只能 `asar: false` 打包，并用 `electron.exe` 临时绕过。

**动作**

- 新增 `.github/workflows/build-win.yml`
- Windows runner：`pnpm install` → `pnpm typecheck` → `pnpm build` → `electron-builder --win`
- 上传安装包 artifact；后续可接 `GH_TOKEN` 发布 Release
- 在 CI 中执行 `check:encryption`，确保 Git 内容为明文

**验收**

- CI 产出的 `CineLab Setup` 安装后可直接启动
- 安装包内 `app.asar` 内容正常
- 构建日志可下载

**收益**

- 彻底绕开本机加密软件
- 为代码签名、自动更新、正式发版打基础

## P1：首次使用体验

### P1-1 模型配置引导

**现状**

`models.json` 为空时，新建项目后 prompt bar 只提示“未配置模型”，用户不知道下一步去哪。

**动作**

- 空配置时在欢迎页和画布给出「配置模型」主入口
- 设置页提供常见 Provider 预设：OpenAI 兼容、可灵、火山方舟、MiniMax、Vidu 等
- 保存后提供「测试连接」，成功再回到画布
- 首次配置完成后给一条轻量提示

**验收**

- 全新用户数据目录下，能从欢迎页走到第一次成功生成
- Key 无效、Base URL 错误、网络超时有明确提示

### P1-2 统一错误与任务反馈

**动作**

- 统一错误码与用户文案映射
- 任务失败统一进 toast + 生成历史，支持重试
- 区分「可重试」（网络/超时/限流）和「不可重试」（Key 无效/参数错误）
- 取消任务后状态明确，不残留 running

**验收**

- 任意生成失败都能看到原因和下一步动作
- 重试不会产生重复任务或重复扣费

## P2：工程质量

### P2-1 最小测试与 CI

**动作**

- 引入 Vitest
- 优先覆盖：
  - `project-schema` / `canvas-schema` 校验
  - `project/manager` 的项目创建、封面读写、最近项目
  - `media` 参数校验与路径安全
- GitHub Actions 增加 `typecheck` + `build` + `check:encryption`
- 现有 CDP 脚本整理成 smoke test（启动、打开项目、建节点）

**验收**

- PR 必须通过 typecheck 与最小测试
- 核心数据读写有回归保护

### P2-2 本地日志与崩溃报告

**动作**

- 接入 `electron-log`
- 主进程、渲染进程、Python worker 的错误统一落盘到用户数据目录
- 设置页「关于」增加「打开日志目录」
- 保留现有 `window-error.log` 作为窗口加载诊断

**验收**

- 打包态出错时，用户能提供一份完整日志
- 日志不包含 API Key 等敏感信息

## P3：功能候选

### P3-1 AGENT-1：Agent 与画布协作

**现状**

`state.json` 中唯一的大型未完成功能。

**动作**

- 先写 `docs/agent-plan.md`，明确交互形态：
  - 对话式创建/连接节点
  - 引用当前选区或指定节点
  - 批量修改参数、生成、整理画布
- 再进入实现

**验收**

- 至少一个完整场景可演示：用户一句话 → Agent 建节点/连线/触发生成
- 所有改动可通过撤销恢复

### P3-2 项目模板与示例项目

**动作**

- 新建项目时提供模板：空白、分镜、产品广告、角色短片
- 模板包含画布结构、节点参数、示例素材和模型占位
- 模板可放在应用资源目录，也可后续做在线模板

**验收**

- 新用户选模板后能直接看到完整画布结构
- 模板项目与普通项目完全兼容

### P3-3 资产库与导出增强

**动作**

- 资产搜索、标签、批量移动/删除
- 视频合成导出：多段拼接、字幕、音轨混合
- 导出预设（分辨率、码率、格式）

**验收**

- 资产数量上百时仍能快速定位
- 多段视频可一次合成导出

## P4：大功能（待单独方案讨论）

以下功能体量较大，先记录方向，不进入当前实施队列。每项开始前单独写 `docs/<feature>-plan.md`，明确交互、技术选型、数据结构和验收标准。

### P4-1 剪辑台

**目标**：在 CineLab 内完成时间线级剪辑，把画布节点、资产库与导出流程串起来。

**候选能力**

- 多轨时间线：视频、音频、字幕、图片轨
- 片段裁切、拖拽、吸附、转场
- 预览播放器与代理视频
- 与画布节点互相引用：节点输出直接拖入时间线

**待决策**

- 自研时间线 UI vs 集成现有剪辑库
- 预览渲染：WebCodecs / Canvas vs ffmpeg 代理
- 工程文件格式与画布项目的边界
- 导出管线复用 ffmpeg filter graph 的方式

**前置**：导出增强、资产库搜索/批量操作

### P4-2 Agent 集成

**目标**：让 Agent 能理解项目与画布，并执行可撤销的创作操作。

**候选能力**

- 对话式创建节点、连线、触发生成
- 引用当前选区、指定节点或整个画布
- 批量修改参数、整理画布、生成分镜
- 外部 Agent / MCP / CLI 接入

**待决策**

- 内置 Agent vs 外部接入优先
- 工具调用协议与权限边界
- 撤销/审计与长任务中断恢复
- 与 `AGENT-1` 的关系：合并为同一立项，还是先做画布内 Agent 再做外部集成

**前置**：稳定的 IPC 工具层、任务队列与错误模型

### P4-3 智能剪辑

**目标**：基于素材内容自动完成粗剪，降低长视频整理成本。

**候选能力**

- 镜头检测与素材分段
- 语音转写、按文案匹配画面
- 节奏点识别、自动卡点
- 一键粗剪后进入剪辑台微调

**待决策**

- 本地模型 vs 云端 API
- 转写、镜头检测、BGM 分析的工具链
- 自动化程度：全自动 vs 建议式

**前置**：剪辑台、资产库、任务队列

### P4-4 超分

**目标**：图片/视频超分辨率，提升生成素材与外部素材的可用分辨率。

**候选能力**

- 图片 2x / 4x 超分
- 视频超分（分块、逐帧或模型原生）
- 与资产库、节点工具栏、导出流程集成
- 复用组件按需下载机制（模型/runtime）

**待决策**

- 本地模型（Real-ESRGAN 等）vs API
- 本地 runtime 体积、GPU 支持与 CPU 回退
- 视频超分的耗时、分块与进度策略
- 是否作为独立节点类型

**前置**：组件下载器复用、任务队列、资产版本栈

## 建议执行顺序

1. P0-1 安装包瘦身
2. P0-3 GitHub Actions Windows 打包
3. P0-2 深度动作捕捉收尾（依赖真实素材与 CI 包）
4. P1-1 模型配置引导
5. P1-2 统一错误反馈
6. P2-1 最小测试与 CI
7. P2-2 日志与崩溃报告
8. P3 功能项按产品优先级单独立项
9. P4 大功能逐项写方案文档后再排期

## 暂不做

- 自动更新（等正式发版和签名稳定后再接）
- 代码签名（需要证书，先确认发布渠道）
- SQLite / 原生模块（继续保持 JSON / JSONL）
- 多人实时协作（当前定位是本地工具）
