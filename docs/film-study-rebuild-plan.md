# 逐帧拉片重构方案

日期：2026-11-18
状态：参考（待实施）
关联：`docs/architecture.md`、`docs/ui-spec.md`、`docs/agent-capabilities.md`

## 1. 背景

当前逐帧拉片是一个独立的分析工具：视频节点 → 拉片节点 → 分镜组 / 分镜表 / 切片 / BGM，另有独立「拉片室」承担段落编辑、结构树、情绪面板和导出。

对 AIGC 创作来说，这个形态有三个问题：

1. 拉片的终点是「分析结果」，不是「可执行的创作图」，用户看完还要手工搭生成流程。
2. 拉片室是独立工作台，对做 AIGC 的人是负担，真正的编辑需求集中在分镜表和单镜详情。
3. 分析深度不足：切镜只做硬切/跳切，没有转场分类、制作方式取证、角色聚合、字幕轨和音频分轨。

本方案把拉片从「分析工具」重构为「画布上游的素材工厂 + 工作流生成器」。

## 2. 目标与原则

### 目标

- 拉片的每个产出都能变成画布节点，可直接连线、可直接生成、可沉淀为资产。
- 删除拉片室，编辑能力收进分镜表浮层和镜头文本节点。
- 复刻从「一份方案」变成「一张可执行的图」。
- 分析深度对齐参考项目 rea-video 的切镜与取证能力，但输出形态按 CineLab 重做。

### 原则

1. **拉片为画布服务**：不为分析而分析，产物必须能进入创作链路。
2. **效果优先**：不为了省节点牺牲信息，节点密度靠分组和视口裁剪解决；每镜的文本节点始终存在，不折叠。
3. **先建图，后生成**：复刻只建节点、连线、分组，不调用模型；生成由用户在节点上主动发起。
4. **手动生成不走提案**：用户点生成就是明确意图，直接入队；只有 CineBot 代操作时才走生成提案。
5. **结论带证据**：每一镜的制作方式、角色、台词都能回到原片对应秒数核对。
6. **可局部重跑**：改一镜的提示词或角色，只重跑该镜，不整片重来。

### 非目标

- 不做独立的拉片报告页或 HTML 报告。
- 不复刻 rea-video 的 VIDEO.md 报告形态和 capsule-cinema 集成。
- 不打包 rea-toon（PolyForm Noncommercial，禁止商用），只借鉴其角色合并、说话人、情绪账的数据设计。
- 不把 Python CV 管线整体移植到 Electron；重模型能力走组件 runtime。
- 不兼容旧 study 数据。

## 3. 画布形态

拉片节点是入口，默认落三类产物，其余按需展开：

```
                        ┌──────────────┐
                        │  角色组       │  角色卡 × N
                        └──────┬───────┘
                               │ 参考图
[视频节点] ──→ [拉片节点] ──→ [分镜表] ──→ [镜头组] ──→ [复刻工作流]
                    │                      （首帧/尾帧/文本）  （按需）
                    ├──→ 场景组
                    ├──→ 风格卡
                    └──→ 音频组
```

默认产物：**拉片节点 + 分镜表 + 镜头组**。
按需产物：角色组、场景组、风格卡、音频组、复刻工作流。

一条 60 秒、30 镜、5 场戏的短剧，默认约 90 个节点（每镜首帧、尾帧、文本）；复刻后约 120 个。100 镜约 400 个，靠按场分组和视口裁剪承载。

## 4. 数据模型 v2

全量分析存 `study/<studyId>.json`，画布节点只存引用。

```ts
interface FilmStudy {
  schemaVersion: 2
  id: string
  sourceNodeId: string
  sourcePath: string
  sourceScope?: AssetScope
  sourceName: string
  duration: number
  fps: number
  frameInterval: number
  frames: FilmStudyFrame[]
  shots: FilmStudyShot[]
  scenes: FilmStudyScene[]
  cast: FilmStudyCast[]
  style?: FilmStudyStyle
  audio?: FilmStudyAudio
  mapping?: FilmStudyMapping
  createdAt: string
  updatedAt: string
}
```

### 4.1 镜头

```ts
interface FilmStudyShot {

### 4.2 场、角色、场景、风格、音频

interface FilmStudyScene {

```

### 4.3 旧数据

- 旧 `study.json` 不读取、不迁移。
- 旧拉片节点不做特殊兼容；读取失败时节点显示 `error`，不阻塞画布。
- 用户重新拉片即可得到 v2 数据。

## 5. 画布节点

### 5.1 拉片节点（复用 `study`）

卡片内容：

```
┌────────────────────────────────────┐
│  《××》第 1 集 · 拉片        [⋯]  │
├────────────────────────────────────┤
│  ┌──────┬──────┬──────┐            │
│  │ 首帧 │ 首帧 │ 首帧 │  联系表封面 │
│  └──────┴──────┴──────┘            │
│  30 镜 · 2:14 · 真人短剧            │
│  实拍 72% · AI 18% · 代码 10%       │
│  12 角色 · 8 场景 · 96 句台词       │
├────────────────────────────────────┤
│ [分镜表] [镜头] [角色] [场景]       │
│ [风格] [音频] [复刻]                │
└────────────────────────────────────┘
```

- 运行中显示四段进度：切镜 → 逐镜理解 → 取证 → 聚合；每段可单独失败降级。
- 底部按钮是「生成节点」的动作，不打开新页面。
- 右键菜单：重新拉片、只重跑某镜、导出 Markdown、导出 JSON、导出 CSV、删除全部产物。
- 节点 data 存 `studyId` 和摘要字段，不复制全量分析。

### 5.2 分镜表（复用 `text`）

整片一个文本节点，Markdown 表格，**只读总览**，不在这里编辑。

| 列 | 内容 |
|---|---|
| 镜号 / 时间 / 时长 | `01 / 00:03.2 / 2.4s` |
| 景别 / 机位 / 运镜 | 特写 / 平视 / 推 |
| 画面 | 一句话描述 |
| 台词 | 说话人 + 台词 |
| 制作方式 | `实拍 86%` / `AI 92%` / `代码 78%` |
| 提示词摘要 | 截断到 40 字 |

双击打开 `FilmStudySheet` 大表格；编辑统一在镜头文本节点或镜头详情浮层。保存时按 `study.shots` 重新生成分镜表。

### 5.3 镜头单元（两个 `image` + 一个 `text`）

不新增 `shot` 节点类型。每个镜头固定三个节点：

```
[07 首 image]  [07 尾 image]  [07 文本]
```

- 首帧、尾帧：`image` 节点，图片来自 `study.shots[i].firstFrame / lastFrame`。
- 文本节点：Markdown，存该镜完整信息，是复刻时的 prompt 来源。
- 三个节点放在同一个分组里，按行排列；始终存在，不折叠。

镜头文本节点的 Markdown 模板：

```markdown
## 镜 07 · 00:12.4–00:15.1（3.2s）

- 景别：中景
- 机位：平视
- 运镜：手持跟拍
- 光线：室内暖光，窗侧逆光
- 画面：林小雨站在门口，手里攥着手机
- 动作：从门口走到沙发前，停下
- 台词：林小雨「你到底瞒了我多久」
- 音效：玻璃碎裂 @14.8s
- 制作方式：实拍 86%
- 证据：传感器噪声 0.42、24fps 无重复帧、人脸占比 34%
- 角色：林小雨（画面左）、陈默（画面右）
- 场景：S1 办公室 · 日

### 提示词

中景，室内暖光，年轻女性站在门口攥着手机，从门口走向沙发，
手持跟拍，轻微晃动，写实电影感，浅景深。
```

- 文本节点可直接连到视频生成节点作为 prompt 输入。
- 双击文本节点进入 Markdown 编辑。
- 详情浮层展示首/中/尾帧、证据和「定位原片」；定位时画布上的视频节点 seek 到该镜起点并播放。

### 5.4 角色组

默认用**抽帧头像**，不是生成：

1. 当前实现取该角色第一次出现镜头的中间帧作为头像，再取最多 3 张作为造型参考。
2. 裁脸（YuNet/OpenCV）是可选增强，尚未接入；没有组件时不影响主流程。
3. 声音样本：从原片人声轨切该角色自己说的几句（R4 接入）。

角色卡（`image` 节点）：

```
┌──────────────┐
│   [抽帧头像] │
│ 林小雨 · 女主 │
│ 18 镜 · 3 造型│
└──────────────┘
```

- 详情：外貌描述、造型列表、声音样本、出现镜头。
- 可选「生成角色参考图」：用抽帧图作参考，生成干净正脸设定图；生成前命名（原片角色名 + 替身，或用户输入），生成后可选存入资产库 `角色/`。
- 右键：加入资产库（角色）/ 用作参考图 / 替换资产。
- 落库后复用现有 `CharacterCard`。

降级：未安装 `depth-runtime`（含 Python + OpenCV）时，角色头像退回该角色出现镜头的中间帧，不做裁脸，不阻塞主流程。

### 5.5 场景组

- 场景卡用抽帧基准图，不是生成。
- 卡片：基准图、地点、时间、光线、出现镜数。
- 详情：场景描述、色调、出现镜头。
- 右键：生成场景基准图（可选）/ 加入资产库（场景）/ 用作参考图。

### 5.6 风格卡（`text`）

- 内容：画风、色调、构图、运镜、节奏、风格提示词。
- 输出端口：文本，可连到任何 prompt 节点。
- 右键：应用到选中镜头 / 保存为风格资产 / 复制提示词。

### 5.7 音频组

- BGM 节点（`audio`）：`BGM · 128 BPM · D 大调`。
- 角色声音样本（`audio`）× N。
- 音效清单（`text`）：时间点、类型、对应画面事件。
- 右键：用作参考音频 / 加入资产库（音频）。

### 5.8 分组策略

- **取消单组数量上限**。`STORYBOARD_MAX_NODES = 25` 只是旧的一次性建组限制，不是渲染限制；`Canvas.tsx` 已开 `onlyRenderVisibleElements`。
- **按 VLM 分场结果分组**：一场一组，组标题 `S1 · 办公室 · 日`。
- 组内每镜一行四格：`[首] [尾] [文本] [生成（复刻后）]`。
- 单场超过 12 镜时拆成「上半场/下半场」两个子组，组名加序号。
- 不折叠；性能靠视口裁剪和缩略图懒加载。

### 5.9 引用与刷新

节点 data 增加：

```ts
studyRef?: {
  studyId: string
  kind: 'shot' | 'cast' | 'scene' | 'style' | 'audio' | 'sheet'
  index?: number   // 镜头号或场号
  key?: string     // 角色/场景 id
}
```

- 重新拉片时按 `studyRef` 找到已有节点，刷新图片和标题，保留用户手改的提示词。
- 删除拉片节点时，按 `studyRef` 删除其产物；用户手动移出的节点保留。
- 单镜重跑只更新该镜对应的首、尾、文本节点。

## 6. 复刻工作流

### 6.1 复刻是什么

复刻不是复制原片文件，也不是自动生成新视频。它做一件事：**按原片的镜头结构，在画布上搭一套「生成同款」的节点图。**

每一镜搭出来的结构：

```
[07 首 image] ──┐
                 ├──→ [视频生成节点]  ←── [07 文本：提示词]
[07 尾 image] ──┘          ▲
                           │
              [角色参考图] [场景参考图]（可选）
```

- 视频生成节点就是普通视频节点，预填 prompt、模型、参考素材。
- 首帧、尾帧是原片抽帧，直接引用，不调用模型。
- 生成节点创建后是待生成状态，不调用模型。
- 角色/场景参考图来自选角/选景映射，用户决定接不接。

### 6.2 三种复刻粒度

| 动作 | 入口 | 建出来的图 |
|---|---|---|
| 复刻这一镜 | 镜头文本节点或详情右键 | 1 组：首/尾/文本 → 生成节点 |
| 复刻选中镜头 | 多选镜头文本节点右键 | N 组，按场分组 |
| 整片复刻 | 拉片节点右键 | 分镜表 + 角色/场景/风格 + 全部镜头组 + 生成组 |

整片复刻也只是建图，不提交任何生成。

### 6.3 选角与选景

点「复刻」时先弹一次映射面板：

- 左列：原片角色 / 场景。
- 右列：选择资产库里的角色/场景；没有合适的可以「新建空白节点」。
- 默认「保持原片」，用抽帧图作为参考；用户主动改才替换。
- 空白节点是普通 `image` 生成节点，预填该角色/场景的外貌描述；**生成前命名**（原片角色名 + 替身，或用户输入），生成后可存入资产库并绑定映射。
- 映射存 `study.mapping`，同一项目下次复刻复用。

### 6.4 复刻输入模式

默认 **B**：

- **B（默认）**：原片首帧 + 用户自己的角色/场景参考图（全能参考），适合换人换景复刻。
- **C（可选）**：原片切片作为参考视频，仅模型支持时可选。
- **首尾帧模式（可选）**：想保留原片动作/构图时选，连首帧 + 尾帧。

制作方式不限制能否生成：实拍镜头同样用 AI 复刻，只是提示词写「写实拍摄」，输入用原片首帧 + 参考图。代码渲染镜头默认也走视频生成，代码重建作为镜头详情里的「高级」选项，不默认建代码节点。

### 6.5 用户确认与生成

复刻建图阶段不调用任何模型。建完后所有生成节点都是「待生成」，卡片上带生成按钮。

- 单镜：点该视频节点的「生成」→ 直接入队（和普通节点一致，不弹提案）。
- 批量：多选节点后点工具栏「生成选中」，或组标题的「生成本组」。
- 不想做的镜头不点，或直接删掉。
- 生成失败不自动重试，节点标 `error`，用户手动点重试。
- 结果写回生成节点自己的版本栈，不新建结果节点。

**生成提案只用于 CineBot 代操作**：Agent 批量提交时仍走现有 `AgentProposal`，用户在 Agent 面板确认后才入队。手动操作不需要提案。

### 6.6 生成之后

- 不自动创建剪辑室节点，不自动建时间线。
- 复刻结果留在各自的生成节点和分组里。
- 用户需要剪辑时：多选生成节点 → 现有「新建剪辑室」入口；或让 CineBot 建时间线。
- 生成视频用原时长，不裁到原片；转场默认硬切，用户在剪辑室改。

### 6.7 音频与字幕

- 默认不带原片音频（版权 + 换人换景后台词可能变）。
- 原片 BGM/音效作为可选 `audio` 节点放在音频组，用户想用再连。
- 字幕默认关闭，用户基于新台词重新生成。
- 原片人声只作为角色声音样本，不进入复刻。

## 7. 拉片室删除

- 删除 `FilmStudyRoom.tsx`、`App.tsx` 引用、`openRoom/closeRoom` 状态、`roomNodeId`。
- `FilmStudySheet` 保留为唯一的大表格界面，从拉片节点 / 分镜表 / 镜头文本节点打开。
- 段落、结构树、情绪面板收进分镜表的「分析」折叠区，不作为主界面。
- 导出 Markdown / JSON / CSV 移到拉片节点右键菜单。
- 旧拉片节点不兼容：读取失败显示 `error`，可删除，不阻塞画布。
- 删除前保留一个可回退 commit。

## 8. 分析链路

### 8.1 切镜

- 在现有 `shot-detect.ts` 基础上移植 rea-video 的渐进式切镜思路：
  - 溶解：中间帧是否为两端帧的线性混合
  - 划像/推移：分块位移 + 方向判定
  - 闪白/淡入淡出：亮度曲线 + 回落到原画面
  - 先低分辨率全片找候选，再对有转场/拿不准的区间加密到逐帧
- 纯 TS，不引入 Python。

### 8.2 关键帧

- 每镜抽首帧、中帧（运动稳定或转折处）、尾帧。
- 首尾帧进入两个 `image` 节点；中帧用于详情和联系表。

### 8.3 分场

- 拉片时自动跑一次 VLM 分场：输入全片联系表 + 镜号/台词表，输出场次范围和地点/时间。
- 代码修正：补齐缺口、去重叠、按镜号排序（对齐 rea-toon 的 `_fix_scenes`）。
- 失败时按每 10 镜兜底，允许用户手动合并/拆分。

### 8.4 逐镜理解

- 复用 CineLab 现有模型配置和 `analysis.ts` 的调用方式。
- 按 5 镜一批送首/中/尾帧拼图，输出景别、运镜、画面、动作、台词、情绪、提示词。
- 只有深度模式，不做快速模式。开始前显示「N 镜、约 M 次调用」，确认后跑。
- 每个镜头记录 `pending/done/error`；失败只重跑未完成镜头；用户改过的 prompt 不覆盖。

### 8.5 制作方式取证

- R1 先做确定性特征：重复帧/帧率指纹、平坦块/调色板、逐帧噪声、背景冻结、整图刚体运动。
- 输出 11 类标签的概率和证据。
- R2 加 VLM 复核：对低置信镜头看图，结果与确定性证据融合。
- 证据保存在 `shot.production.evidence`，镜头详情可展开。

### 8.6 角色、场景、风格、音频

- 角色：抽帧裁脸 + 造型挑选 + 声音切片；可选生成参考图。
- 场景：抽帧基准图 + 光线/色调聚合。
- 风格：从全片统计色调、构图、运镜、节奏，生成风格卡。
- 音频：BGM 提取、人声分轨、音效对齐画面事件。
- 字幕：优先内嵌字幕；无字幕时可选 OCR（组件 runtime，R4）。

### 8.7 局部重跑

- 镜头详情提供「只重跑这一镜」。
- 单镜重跑只更新该镜的 frames、production、cast、prompt，不整片重来。
- 用户手改过的 prompt 用 `edited` 标记保护，重跑默认不覆盖。

## 9. CineBot 上下文

现有 `filmBridge.ts` 的摘要会把最多 24 个 segment 和 5 个宏观字段塞进上下文（每个截断 800 字），新模型下太重。改为三层：

### L0 每轮携带（约 200 token）

```json
{
  "studyId": "…",
  "sourceName": "《××》第 1 集",
  "duration": 134.2,
  "shotCount": 30,
  "sceneCount": 5,
  "production": { "live": 0.72, "ai": 0.18, "code": 0.10 },
  "cast": [{ "id": "lin", "name": "林小雨", "role": "女主" }],
  "scenes": [{ "id": "S1", "name": "办公室 · 日", "shots": [1, 8] }],
  "remake": { "total": 30, "generated": 12, "pending": 18 },
  "selectedShot": 7
}
```

- `cast` 最多 5 个，`scenes` 最多 8 个；超出截断并标 `truncated`。
- 不含单镜描述和提示词。

### L1 按需读取

- `film.get(studyId)`：完整场次、角色、镜头列表。
- `film.getShot(studyId, index)`：单镜详情、证据、提示词。

## 10. 性能与信息密度

- 默认只落拉片节点 + 分镜表 + 镜头组；其余按需生成。
- 镜头组按场分组，每镜一行四格；单场超过 12 镜拆子组。
- 缩略图懒加载，视口外不请求。
- 已有 `onlyRenderVisibleElements`。
- 验收指标：
  - 100 镜项目打开到可操作 < 3 秒
  - 拖拽/缩放平均帧率 ≥ 50fps（视口内 80 节点以内）
  - 内存增量 < 500MB
- 自动布局：拉片在视频下方，分镜表在右，镜头组在分镜表下方，角色/场景/风格在左，复刻工作流在右。
- 新增产物后 `fitView` 到新增区域，不跳回原点。

## 12. 验收标准

### 功能

- 一条 60 秒短剧：拉片 → 默认落拉片节点、分镜表、按场分组的镜头三节点（首/尾/文本）。
- 每个镜头有首帧、尾帧、文本节点；文本节点是 Markdown，可直接连生成节点。
- 角色组默认为抽帧头像；生成参考图是可选动作。
- 选中 3 镜「复刻选中镜头」→ 画布出现 3 个待生成视频节点，预填 prompt、首尾帧、模型，没有模型调用。
- 点其中 1 个节点的「生成」→ 直接入队，不弹提案；失败不自动重试。
- 点「定位原片」→ 视频节点 seek 到对应秒数并播放。
- 不自动创建剪辑室；用户用现有入口或 CineBot 建时间线。

### 数据

- 旧 study 不读取、不迁移；旧拉片节点读取失败显示 `error`，不阻塞画布。
- 重新拉片不重复建节点，保留用户手改的 prompt。
- 单镜重跑只更新该镜的三个节点。

### 性能

- 100 镜（约 400 节点）：打开 < 3 秒、视口内 80 节点拖拽 ≥ 50fps、内存增量 < 500MB。

### 文档

- `docs/ui-spec.md` 的拉片章节同步更新。
- `docs/agent-capabilities.md` 的 `film.*` 工具按新清单更新。
- `corepack pnpm check:docs` 通过。

## 13. 风险

| 风险 | 处理 |
|---|---|
| 每镜三节点导致节点数增长 | 按场分组 + 视口裁剪 + 缩略图懒加载，100 镜压测 |
| 切镜算法替换后不稳定 | R1 先建用户自建评测集，回退开关保留旧检测 |
| 角色裁脸依赖 `depth-runtime` | 未安装时降级为中间帧，不阻塞 |
| 模型能力差异导致复刻连线不一致 | 建图时按 `effectiveCapabilities` 校验，换模型后重新校验 |
| 手动生成误触 | 生成按钮放在节点卡片上，二次点击确认；批量生成在组标题栏 |
| rea-video 迭代快，算法参考会过期 | 只移植算法思路，不依赖其包和输出格式 |

## 14. 不做的事

- 不做独立拉片报告页。
- 不做快速模式。
- 不兼容旧 study 数据。
- 不自动创建剪辑室或时间线。
- 手动生成不走提案；提案只用于 CineBot 代操作。
- 不打包 rea-toon。
- 不把 Python CV 管线整体搬进 Electron。
